# DR staging and owner-controlled Ark1 append gate

## Security model

GitHub Actions and its Workload Identity service account can write only to a separate, user-owned staging spreadsheet. The GitHub code contains no Sheets API client for the original spreadsheet, and no workflow secret or flag can enable a direct write to it. The staging writer is serialized by the existing catalogue workflow, validates the full staging schema and exact Podcast-ID, appends with `RAW`, and stops on ambiguous or duplicate identities. The integrated workflow runs in append-only mode: it never changes an existing staging row or cell, including blank host cells.

The append into original `Ark1` is a separate Apps Script bound to that spreadsheet. The service account must not have any access to the original workbook. **Ejerstyret staging → Gennemgå og godkend samlet** opens one read-only sidebar across Bakspejl, Djævlen i detaljen, Tyran and Et kapitel for sig. It shows exact IDs, official source URLs, individual covers, genre and review status, plus the protected Mattias and Marcos identities. `SOURCE_VERIFIED_REQUIRES_OWNER_APPROVAL` and individually reviewed `EDITORIALLY_APPROVED_SOURCE_VERIFIED` rows can be selected together. `NEEDS_EDITORIAL_REVIEW` rows show their missing evidence and stay excluded. Radio IIII changes to the owner-approved genre `Samfund` only in newly appended Ark1 rows; staging stays unchanged.

The owner makes one fresh, independent full copy using a separate backup identity and restores it to a test spreadsheet before approval. The backup file must not be shared with the bound Apps Script owner account, GitHub service account, or staging workflow. (A file merely hidden from the code is not an access boundary.) The writer script never opens or receives the backup ID. In the sidebar, the owner attests to that completed backup and test restore and clicks **Godkend valgte samlet** once. This explicit, immediate owner attestation replaces per-batch property edits; no backup ID or timestamp is copied or refreshed in Script Properties. Google Apps Script does not provide a way for this bound writer to independently verify a restore while keeping the backup inaccessible to it. Automating that proof needs a separately authorized backup identity and a trusted receipt protocol, which this project does not have. The sidebar states this limitation rather than claiming a machine-verified backup.

The batch holds one document lock, rechecks staging and target snapshots, all IDs, protected identities and source/GUID/cover collisions before the first write, reads each new row back, and compares all prior Ark1 values and formulas. The write gate opens only during the locked attempt and closes automatically after approval or error. It appends only: it has no update/delete/sort/clear path. Failed writes are reported with IDs that were verified, attempted, and not attempted; there is no blind retry. Read-only preview does not require a backup and never writes.

This owner-run bridge requires a person to review and approve every batch. Google Sheets Editor permission is not technically append-only; the stronger boundary is that the GitHub service account has no permission on the original workbook and cannot invoke the owner-bound script as the owner. Do not install a time-driven trigger or enable unattended append until an independent security review explicitly approves that change.

Tyran proposals reuse the same `DR staging` tab and exact existing headers. The scheduled staging workflow reads `data/auto-discovered-tyran.json`, validates the immutable Macias and Marcos identities against their DR series pages, first full episodes, individual 720×720 covers and SHA-256 checksums, then stages only Macias. Marcos is the existing Ark1 Podcast-ID `marcos`; it is validated and skipped. The 22 protected historical Tyran identities remain protected. Provenance is carried in the existing `DR source description` field so no staging columns or workflow jobs are added. Proposals remain `NEEDS_EDITORIAL_REVIEW` until an owner completes an individual editorial review and source verification, fills the required host, active genre and topics, and changes the review status to `EDITORIALLY_APPROVED_SOURCE_VERIFIED`. Episode feeds, ratings and history remain blank.

The current staging sheet contains two one-cell notes reading `Macias` in the DR source GUID column. Neither has a Podcast-ID or other identity fields. The workflow reports and preserves both unchanged; any orphan row containing a title, main series, URL, or numeric GUID remains a hard stop for manual review. DR proposals are written to an explicit row after the last populated row, then checked across all columns. The Sheets append endpoint is not used because a lone provenance-column note can make its table detection choose the wrong target.

The legacy **DR staging → Gennemgå Tyran-forslag (ejerstyret)**, DR and Radio IIII actions remain available. The shared batch excludes Tyran rows until individual editorial review and official source evidence are recorded with the status `EDITORIALLY_APPROVED_SOURCE_VERIFIED`; it checks structured provenance and the source-description digest before treating the row as eligible. Marcos and any matching title, source, episode GUID, series ID, production number, cover or protected historical identity are never appended as a duplicate. The Apps Script is not installed or activated by this repository change.

## Source metadata for future DR series

Verified DR metadata records remain tied to exact immutable Podcast-IDs and full DR episode URLs. The existing legacy identity `dræberurten` is bound to the official full episode `16122692641` and remains marked for owner review. For future discoveries, `dr-full-standalone-discovery.mjs` records the official full-episode GUID, URL, title, and DR description when it can validate an active, sufficiently long full episode and an unambiguous route. It extracts a host only from an explicit DR credit label containing “vært”, including combined roles such as “Tilrettelæggelse, vært og lyddesign”. Guest, contributor, producer, editor and organizer credits do not qualify by themselves. Conflicting or absent host credits leave the field blank and require editorial review; umbrella-show hosts are never copied to child series. The staging builder sanitizes source text and can produce a short excerpt and bounded long description without inventing facts. Secondary genre, episode count, topics and similarities remain blank unless supplied by verified source or curated metadata. Missing, teaser-only, malformed, conflicting, or incomplete provenance is never made append-eligible; the row is withheld or marked for editorial review. The owner sees the exact source URL/text and proposed host and must review the entry before the Ark1 gate. Future fully verified proposals can use the same owner-approved batch sidebar.

No additional polling job is introduced: the existing scheduled catalogue workflow reuses its current discovery and catalogue sync. Existing descriptions are preserved when discovery cannot verify replacement metadata.

## Existing infrastructure (one time)

The sharing, staging, GitHub federation, and workflow setup below is only needed if the existing staging infrastructure is not already configured. Do not repeat it for a batch.

1. In the original spreadsheet's sharing dialog, confirm that no GitHub service account or other automation identity can edit the original workbook.
2. Keep DR and Radio IIII staging in the separate user-owned staging workbook with the exact existing headers. Keep the two standalone `Macias` notes untouched.
3. Share only the staging workbook with the dedicated service account. Keep the original and backup inaccessible to that account and to GitHub Actions.
4. Keep the existing Workload Identity provider restricted to this repository's trusted `main` workflow and the dedicated staging account. Do not grant OIDC access to pull request workflows.

## Update the existing bound Apps Script once

Replace the existing `Code.gs` contents with the reviewed `apps-script/append-dr-staging-to-ark1/Code.gs`, save, and reload the original spreadsheet. The sidebar HTML is embedded in this file; no other Apps Script file, manifest, trigger, or menu needs replacement. Preserve the existing project and its other files. Keep the one-time `OWNER_EMAIL` and `STAGING_SPREADSHEET_ID` settings; the shared batch no longer reads or asks the owner to change `BACKUP_SPREADSHEET_ID`, `BACKUP_VERIFIED_AT`, `BACKUP_RESTORE_TEST_VERIFIED`, or `APPEND_ENABLED`.

One-click installation from this repository is intentionally not included. Google's Apps Script `projects.updateContent` operation replaces the project's files and requires the `script.projects` OAuth scope; using it would add broad project-management authorization and risk overwriting other bound-script files. The safe available install is a one-time update in the existing script editor. No Apps Script change or production write is performed by this repository PR. See Google's [Apps Script project update API](https://developers.google.com/apps-script/api/reference/rest/v1/projects/updateContent) and [project management guidance](https://developers.google.com/apps-script/api/how-tos/manage-projects).

## Each approved batch

1. Using a separate backup identity whose files are not shared with the bound Apps Script owner account, GitHub automation, or staging workflow, make one fresh full copy of the original workbook. Restore the copy as a test spreadsheet and verify its tabs and data. Do not rely on protected ranges or version history alone.
2. Reload the original workbook and open **Ejerstyret staging → Gennemgå og godkend samlet**. Check the displayed identities, official sources, covers, genres, and review statuses. Only validated, new rows can be selected; editorial-review rows remain excluded.
3. Check the backup attestation and click **Godkend valgte samlet** once. This attests that the backup and test restore in step 1 have just been completed; the backup itself remains inaccessible to the writer script.
4. Read the success or stop report in the sidebar. For a failure, note the exact verified, attempted, and unattempted IDs and resolve it manually before another attempt. Never blindly retry.

The shared Apps Script tests cover the read-only sidebar preview, one owner confirmation and backup attestation, exact sources and covers for all five proposals, dynamic guests from all four series, protected Mattias and Marcos identities, document locking, target/staging snapshots, partial-write reporting, idempotency, automatic gate closure, and unchanged ratings/history. Radio IIII tests additionally cover all four immutable guest identities, A:AJ-only reads, exact season/GUID/source/cover checks, inactive-genre refusal and the preserved legacy menu. Tests never authenticate to Google or mutate production. Production activation remains disabled until the owner has completed the Cloud, sharing, backup and Apps Script setup above and independently reviewed the results.
